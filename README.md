# Практикалық жұмыс №8

10-нұсқа: бұлттық файлдар жүйесі. №5-7 жобасының жалғасы.
Файлдың атауы, MIME түрі және көлемі PostgreSQL базасында сақталады. Файл мазмұнын жүктеу бұл жобаның міндетіне кірмейді.

Жария бет: https://cloud-files-practice5-variant10.onrender.com/demo
Репозиторий: https://github.com/rensxm/cloud-files-practice5-variant10

## Компьютерде іске қосу

1. Node.js орнатыңыз. Жоба бумасында PowerShell ашыңыз.
2. `npm.cmd install` орындаңыз.
3. `.env.example` файлын `.env` деп көшіріңіз.
4. `.env` ішіне өз PostgreSQL базаңыздың DATABASE_URL мәнін жазыңыз. Render External Database URL қолдансаңыз, DATABASE_SSL жолын алып тастаңыз. Жергілікті PostgreSQL үшін DATABASE_SSL=disable қалдырыңыз.
5. PORT=3004, APP_ENV=development, STUDENT_VARIANT=10 беріңіз.
6. Жаңа база болса, `npm.cmd run db:init` орындаңыз. Кесте мен 5 мысал жазба қосылады. Бұрынғы жазбалар жойылмайды.
7. `npm.cmd start` орындаңыз.
8. http://localhost:3004/demo ашыңыз.

Нақты .env құпия файл. Ол GitHub пен архивке қосылмайды.

## Маршруттар

| Әдіс | Адрес | Нәтиже |
|---|---|---|
| GET | /api/files | Барлық файл мәліметі, 200 |
| GET | /api/files/:id | Бір жазба, 200; жоқ болса 404 |
| POST | /api/files | Жаңа жазба, 201 |
| PUT | /api/files/:id | Үш өрісті толық жаңарту, 200; жоқ болса 404 |
| GET | /health | Қолданба күйі, 200 |
| GET | /health/db | База күйі, 200 немесе 503 |

POST және PUT бірдей тексеруді қолданады: name және content_type бос емес мәтін, size_bytes теріс емес бүтін сан. Қате сұраныс 400 береді. Қайталанған атау 409 береді. SQL мәндері $1...$4 параметрлерімен беріледі.

## Браузерде тексеру

«Барлық файлды оқу» батырмасы кестені ашады. Жаңа, бұрын қолданылмаған атау енгізіп, POST басыңыз. Жауапта 201 және жаңа ID шығады. Сол ID автоматты таңдалады. Көлемді өзгертіп, PUT басыңыз: 200 шығады. «Бір файлды оқу» арқылы өзгеріс базада сақталғанын тексеріңіз. Өзге жазбаны өзгерту үшін кестедегі «Таңдау» батырмасын қолданыңыз.

## Бұлттық орта

Render Web Service және PostgreSQL бөлек қызметтер. Build: npm install. Start: npm start. DATABASE_URL Environment ішінде, APP_ENV=production, STUDENT_VARIANT=10. Render ішкі URL үшін DATABASE_SSL=disable қолданылады. Сыртқы қосылым TLS сертификатын тексереді. Docker/VM міндетті емес.

## Ақауды тексеру және қалпына келтіру

Оқу сервисінде DATABASE_URL ішіндегі база атауын уақытша жоқ атауға ауыстырып, қайта жариялаңыз. /health 200, /health/db 503, /api/files 500 береді. Runtime log ішінде DB_HEALTH_ERROR, SERVER_ERROR және 3D000 көрінеді. Құпия URL журналға шығарылмайды. Дұрыс URL-ді қайтарып, қайта жариялаңыз. Health DB, барлық файл және жаңартылған жазба қайтадан 200 беруі керек. Қате баптауды қалдырмаңыз.

Бұл оқу API-ы. Жеке кабинет пен рөлдер әлі қосылмаған. Нақты жеке файлдарды сақтайтын жүйеге айналдыру үшін кіруді тексеру, құқықтарды бөлу, резервтік көшіру және файл мазмұнына арналған сақтау қызметі қажет.
